# קורט — ספר המתכונים שלי

מערכת מתכונים אישית בעברית, מותאמת לנייד ולמחשב, מבוססת React, TypeScript, Vite ו־Supabase.

## מצב נוכחי

המערכת עובדת במצב מקומי, ללא חשבונות או משתני סביבה. אפשר ליצור ולערוך מתכונים, לחפש, לסמן מועדפים ולשמור אותם בדפדפן. הוכן גם חיבור Supabase לשלב הבא; המיגרציה עדיין לא הורצה ולא נשמרו נתונים בענן. הקוד עדיין לא הועלה למאגר GitHub.

## מה יש בגרסה הראשונה

- התחברות והרשמה עם אימייל וסיסמה באמצעות Supabase Auth.
- הוספה, עריכה ומחיקה של מתכונים אישיים, עם אישור מחיקה.
- שמירה מקומית שנשארת אחרי טעינה מחדש של הדף, בלי הרשמה.
- הורדת גיבוי JSON וייבוא שלו, עם בדיקת תקינות ומניעת כפילויות.
- מצרכים, שלבי הכנה, קטגוריות, זמן הכנה ובישול, מספר מנות וקישור לתמונה.
- חיפוש לפי שם, תיאור או מצרך; סינון קטגוריות ומועדפים; מיון לפי זמן, שם או עדכון אחרון.
- סימון מצרכים בזמן ההכנה (הסימון זמני ואינו משנה את המתכון).
- הרשאות RLS והקצאות מפורשות: לכל משתמש גישה רק לשורות שלו.
- לשונית נפרדת עם מתכונים להשראה. אפשר לשמור עותק אישי של מתכון לדוגמה.

## הרצה מקומית

דרוש Node.js 24 ומעלה.

```sh
npm ci
npm run dev
```

ברירת המחדל של Vite היא `http://localhost:5173`. אין צורך בקובץ סביבה כדי לעבוד מקומית. מומלץ להישאר באותה כתובת ובאותו דפדפן: נתונים מקומיים שייכים למקור שבו נוצרו, ואינם עוברים אוטומטית לכתובת, למכשיר או לדפדפן אחר.

## שמירה מקומית וגיבוי

הספר המקומי מתחיל ריק; מתכוני ההשראה אינם נרשמים לתוכו בלי בחירה מפורשת. שינויים נשמרים ב־`localStorage` תחת `kort:recipes:v1`. עדכונים מלשונית אחרת של אותו דפדפן נטענים ברשימה. שגיאת כתיבה אינה מוצגת כהצלחה ואינה מוחקת את הספר הקיים. במקרה של נתונים פגומים אפשר להוריד עותק לשחזור, והמערכת אינה דורסת אותם.

- **גיבוי** מוריד קובץ JSON של הספר האישי; הוא אינו כולל סיסמאות או פרטי התחברות.
- **ייבוא גיבוי** מוסיף מתכונים לספר, בלי למחוק מתכונים קיימים. קבצים לא תקינים נדחים לפני הכתיבה. מותר קובץ עד 5MB ועד 2,000 מתכונים בספר המקומי.
- מתכונים זהים מדולגים בייבוא חוזר; שינוי סימון מועדף אינו יוצר כפילות.
- ניקוי נתוני האתר בדפדפן מוחק את הספר המקומי, ולכן כדאי להוריד גיבוי מדי פעם.
- לאחר חיבור הענן והתחברות, תופיע אפשרות **העתקה לחשבון שלי**. היא מעתיקה את הספר המקומי לחשבון הנוכחי ושומרת גם את המקור המקומי. אין העברה אוטומטית לחשבון כלשהו.

## חיבור Supabase

1. לבחור במפורש את הפרויקט המיועד. אין להריץ את המיגרציה בפרויקט גיבוי.
2. לבדוק שאין בו כבר אובייקטים עם הקידומת `recipe_book_`.
3. להריץ את `supabase/migrations/20261024180101_recipe_book.sql` דרך SQL Editor או כלי המיגרציות של Supabase. זו מיגרציה חד־פעמית; אין להריץ אותה שוב אם כבר הוחלה. היא יוצרת טבלה, אינדקס, מדיניות גישה וטריגר חדשים בלבד. היא אינה משנה טבלאות או הגדרות אימות קיימות.
4. להעתיק את `.env.example` ל־`.env.local` ולהגדיר:

   ```dotenv
   VITE_SUPABASE_URL=https://YOUR_PROJECT.supabase.co
   VITE_SUPABASE_PUBLISHABLE_KEY=sb_publishable_...
   ```

5. להשתמש **רק** במפתח publishable לדפדפן. אין להגדיר `service_role`, מפתח secret או סיסמת מסד נתונים במשתנה `VITE_*`.
6. להתחיל מחדש את שרת הפיתוח לאחר שינוי משתני הסביבה. בפרסום האתר יש להגדיר אותם בזמן הבנייה.
7. התחברות באימייל צריכה להיות זמינה בפרויקט. אם נדרש אישור אימייל, המשתמש מאשר את האימייל ואז חוזר לאפליקציה ומתחבר. משלוח אימיילים כפוף להגדרות ולמגבלות Supabase; אין לשנות הגדרות Auth משותפות למערכות אחרות בלי לבדוק את השפעתן.

### בדיקה לאחר החיבור

יש לבדוק עם שני משתמשי בדיקה נפרדים: ליצור מתכון כמשתמש א', לוודא שאינו מופיע למשתמש ב' ושב' אינו יכול לעדכן או למחוק אותו גם דרך ה־API; לוודא שקריאה ללא התחברות נדחית. לאחר מכן לבדוק יצירה, עריכה, מועדפים, מחיקה וטעינה מחדש במשתמש א'. את בדיקות הענן האלה עדיין לא היה אפשר להריץ.

```sql
select tablename, rowsecurity from pg_tables
where schemaname = 'public' and tablename = 'recipe_book_recipes';

select policyname, cmd, roles, qual, with_check from pg_policies
where schemaname = 'public' and tablename = 'recipe_book_recipes';
```

## בדיקות ובנייה

```sh
npm test
npm run build
npm run preview
```

15 בדיקות עברו מקומית:

- קלט, חיפוש וקישורי תמונות.
- שמירה, עדכון ומחיקה מקומיים; גיבוי, ייבוא חוזר ללא כפילויות, קבצים פגומים ואחסון מלא.
- חמישה תרחישי ממשק ב־React ו־jsdom: יצירה, טעינה מחדש, חיפוש, מועדפים, עריכה ומחיקה; העתקת מתכון להשראה; ייבוא; וטיפול בכשלי אחסון.
- הרצת המיגרציה במנוע Postgres מבודד (PGlite): חסימת משתמש לא מחובר, הפרדה בין שני משתמשים ומניעת שינוי בעלות.

בדיקות אלה אינן מחליפות בדיקה בפרויקט Supabase לאחר החיבור. `build` בודק טיפוסים ויוצר את `dist/`; הוא עבר בהצלחה. טרם נערכה בדיקה חזותית בדפדפן. קיים גם GitHub Actions לבדיקות ובנייה, שיפעל לאחר העלאת הקוד למאגר.

## העלאה ל־GitHub

לאחר יצירת מאגר פרטי וריק ב־`https://github.com/new` בשם `recipes`, ניתן לדחוף את ההיסטוריה המקומית:

```sh
git remote add origin https://github.com/h0527040060-debug/recipes.git
git push -u origin main
```

אין צורך לשדרג GitHub לצורך שמירת הקוד. התיקייה `dist/` מתאימה לאירוח סטטי, אבל האתר טרם פורסם. GitHub Pages בחשבון Free מחייב מאגר ציבורי; אין להפוך את המאגר לציבורי בלי החלטה מפורשת של הבעלים.

## מגבלות הגרסה

תמונות מוצגות מקישור HTTPS; העלאת קבצים ו־Storage אינם כלולים עדיין. הגופנים נטענים מ־Google Fonts עם גופן מערכת חלופי, ותמונות הדוגמה מ־Unsplash. קישור שבור בכרטיס או בפרטי מתכון מוחלף בתצוגה חלופית. אין בשלב זה שיתוף מתכונים בין משתמשים, יבוא מאתרים או יצירת מתכונים בעזרת AI.
