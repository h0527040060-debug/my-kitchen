# המטבח שלי

אפליקציית מתכונים ובישול אישית בעברית, המיועדת לבעלים יחיד ולכמה מכשירים שלו. הקוד בבעלותך: React/TypeScript, שרת Node, PostgreSQL, אחסון מדיה פרטי ותור worker מתמשך. אין תלות ב־Base44 ואין מנגנון משפחות, הזמנות או שיתוף משתמשים.

הגרסה החדשה שומרת נתונים **בשרת**, ולא מסתמכת על הודעת ״נשמר״ מקומית. הקוד הקודם נשמר בארכיון ובנתיב `/legacy`; הוא אינו מסד הנתונים של המוצר החדש.

## המסלול המועדף: ענן חינמי, בלי מחשב דולק

מדריך ההפעלה בענן נמצא ב־[docs/CLOUD-FREE.md](docs/CLOUD-FREE.md). קובץ `render.yaml` מגדיר שירות Web אחד ב־Render Free, עם API ו־worker בתהליכים נפרדים, PostgreSQL חיצוני ואחסון S3 פרטי. פרופיל זה מסרב להסתמך על קבצים מקומיים מתכלים. אין שירות worker בתשלום, אין disk בתשלום ואין מסד Render שפג אחרי תקופת ניסיון.

כתובת האפליקציה: **https://my-kitchen-k4w7.onrender.com**. המסד והמדיה נמצאים בפרויקט Neon Free ייעודי, עם אחסון S3 פרטי. יצירת פרויקט Supabase נדחתה בשל מכסת שני פרויקטים פעילים; מערכות Supabase הקיימות לא שונו. כניסה ראשונה והיכן למצוא את הסיסמה: [מדריך הענן](docs/CLOUD-FREE.md).

זהו מסלול עם מגבלות: השרת עשוי להירדם אחרי חוסר פעילות והעיבוד יושהה עד שיתעורר; התור והמדיה נשמרים מחוץ לו. המחשב האישי אינו נדרש להפעלה שוטפת; ההנחיות המקומיות בהמשך הן חלופה לפיתוח.

## ייבוא דרך ChatGPT ו־Drive, ללא מפתח AI API

לאוסף גדול מעלים תמונות לתיקיית Drive הפרטית, וליום־יום אפשר לצרף תמונות לשיחה הקבועה ב־ChatGPT Work. כותבים „עבד את התמונות החדשות”; השיחה קוראת את התמונות ושולחת לאפליקציה מקורות וטיוטות מובנות. הנתונים והסיווג נשארים לבדיקה ולאישור. אין קריאת מודל בתשלום בצד השרת, ו־`AI_DAILY_MAX_CALLS=0` נשאר בתוקף.

תיקיית Drive נפתחת מתוך כרטיס „מתכונים מהצ׳אט ומ־Drive” בתור הייבוא. אין צורך במחשב דולק או בהתקנת תוסף חדש. משתמשים בחיבורי Google Drive ו־Neon ובכלי הרצה בענן של שיחת Work. העלאה לתיקייה אינה מפעילה עיבוד מעצמה: הודעה בשיחה היא הטריגר. אוסף גדול מעובד באצוות עם מצב מתמשך; מכסות המנוי עדיין חלות.

[הוראות שימוש ותהליך ההעברה המאובטח](docs/CHAT-IMPORT.md). אם העברה ישירה מהשיחה אינה זמינה, קיים גם מסך ייבוא חבילת JSON עם תמונות המקור. שידור חוזר ושימוש בשתי הדרכים אינם דורסים תיקון ואינם משכפלים אותו צילום.

אפשר לבקש בשיחה גם תמונות המחשה נפרדות למתכונים ולקטגוריות, לאחר בדיקת המקורות. אין קריאת יצירה מהשרת. התמונות מסומנות כ־AI, והמקורות נשארים זמינים לצדן בראש המתכון ובגלריה. [פרטי ההעברה וסידור קטגוריות](docs/ARTWORK-IMPORT.md). מסכי העריכה מחולקים ללשוניות קצרות, ומידע נוסף על מצרכים ושלבים נפתח לפי הצורך.

## להתחיל במחשב, בלי לבחור אירוח בתשלום

דרושים [Docker Desktop](https://www.docker.com/products/docker-desktop/) ו־Node.js 24. לאחר חילוץ הקוד לתיקייה, פותחים בה מסוף ומבצעים:

```sh
npm run setup
docker compose up -d --build
```

הפקודה הראשונה יוצרת `.env` פרטי עם סיסמאות אקראיות נפרדות למשתמש היישום ולמנהל אתחול המסד. היא אינה מחליפה קובץ קיים. הפקודה השנייה מפעילה מסד, שרת ו־worker עם volumes לשמירת המידע. הבנייה הראשונה יכולה להימשך כמה דקות.

יוצרים את החשבון האישי פעם אחת:

```sh
docker compose exec api npm run owner:create
```

מקלידים אימייל וסיסמה באורך 12 תווים לפחות. הסיסמה אינה מוצגת במסוף. אין מסלול הרשמה ציבורי או חשבון עם סיסמת ברירת מחדל.

פותחים **http://localhost:3000** באותו מחשב ומתחברים. כדי להיכנס מטלפון או ממכשיר נוסף יש להשלים כתובת HTTPS בשרת נגיש; הפעלת המחשב המקומי כשלעצמה אינה כתובת אינטרנט ציבורית.

אם השרת עדיין עולה:

```sh
docker compose ps
docker compose logs --tail=40 api worker
```

לעצירה שממשיכה לשמור את הנתונים:

```sh
docker compose down
```

אין להוסיף `-v` לפקודה זו אלא כאשר מתכוונים למחוק את הנתונים והקבצים שב־volumes.

## מה ניתן לעשות

- הזנה ועריכה ידנית של מתכון, מקור וסיפור, קבוצות מצרכים ושלבים, חלופות, ציוד, זמני עבודה וזמן כולל.
- שברים, טווחים, ״לפי הטעם״ ותפוקה במנות, חלות, יחידות או תבניות; התאמה מדויקת מהבסיס ללא AI וללא שינוי המתכון המקורי.
- ברירת מחדל M רק לביצים שלמות עם מספר ידוע וללא גודל; גרמים, חלבונים, חלמונים וגודל מפורש אינם מוחלפים.
- צילום ובחירת תמונות רבות, עד שלוש בקשות העלאה במקביל בפרופיל הרגיל ואחת בענן החינמי, SHA-256 למניעת כפילות קובץ, קיבוץ וסידור מקורות, פיצול לטיוטות ו־worker שימשיך לאחר סגירת הדפדפן כל עוד השירות ער.
- חילוץ בשיחה וטיוטות מתמשכות עם מקור ואי־ודאות; אין OCR בתשלום בשרת.
- עץ קטגוריות רב־רמות עם אישור מחייב, אישור אצווה ומניעת יצירת אותו ענף פעמיים. תמונת נושא נבחרת אוטומטית מספריית המחשות AI מובנית, ומעובדת באחסון הפרטי ללא מפתח API.
- מקור קריא בגלריה, זום, חיתוך רגיל, סדר וכיתובים, צילומים אישיים, תמונות המחשה קיימות עם סימון מקור, סרטונים שעוברים FFmpeg והקלטות. תמונת AI נשארת מסומנת גם לאחר חיתוך.
- מצב בישול עם snapshot קבוע, צ׳קליסט מצרכים ושלבים, תצוגת שלב גדול, שינוי כמות באישור, טיימרים מתמשכים, דירוג והערות ניסיון.
- חיפוש, סינון ומיון, אוספים לפי מקור, מצרכים בבית עם התחשבות בכמות ידועה ובחלופות, ארוחות ותוכניות הכנה לפי ציוד ותלויות, קניות עם שימור עריכות וסימונים.
- היסטוריית גרסאות, שחזור לטיוטה, סל מחזור, שכפול ארוחה ויכולות קול של הדפדפן כאשר נתמכות, ללא שירות קול בשרת.
- ייצוא נתונים, וכן פקודות נפרדות לגיבוי ולשחזור הכוללים **גם את הקבצים עצמם**.

מידע שלא נקרא אינו מושלם מהדמיון: אפשר לשמור במאגר גם בלי שם, תפוקה, מצרכים, שלבים או קטגוריה. החוסרים נשארים מסומנים להשלמה אפשרית בהמשך; תפוקה תקינה נדרשת רק להתאמת כמויות. ניתן לבשל ולקנות בכמויות המקור גם בלי תפוקה. זמן חסר נשאר לא ידוע, לא אפס. כשרות והיעדר אלרגנים אינם מאושרים לפי תמונה בלבד.

## ללא פעולות ספק AI

לבקשת הבעלים הוסרו עוזר הבישול, חיפוש טבעי, OCR בשרת, יצירה ועריכת תמונות לפי הנחיה, הצעת תפריט ותמלול/הקראה בשרת. הכפתורים ונתיבי HTTP הוסרו. עבודות ספק ישנות לא נשלחות. הזנת מפתח במשתני הסביבה אינה מפעילה אותן מחדש. הייבוא בשיחת Work ותמונות קטגוריה מהספרייה המובנית פועלים ללא API בתשלום.

## בחירת עיצוב בנייד והתקנה באנדרואיד

פתח `/designs` ובחר בין מרווה, לילה ונקי וחד. אפשר לעבור בין העיצובים ולטייל בכל מסכי היישום עם נתונים אמיתיים. רק „בחירה בעיצוב הזה” שומרת את העיצוב לחשבון ולכל מכשיריו. בתצוגת טלפון נשארות שתי עמודות גם ברוחב 320 פיקסלים. כותרת הבית אינה משוכפלת; כלי סינון ופעולות אוסף נפתחים לפי הצורך.

Chrome/דפדפן Android תומך שמדווח `beforeinstallprompt` מציג הצעה להתקין, עם כפתור התקנה ודחייה לשבעה ימים. אין הצעה בתוך מצב standalone, ואירוע appinstalled מסתיר אותה. בדפדפן שאינו מספק את האירוע יש קישור „התקנה במסך הבית” תחת עוד עם צעדי תפריט. קיימים manifest ואייקוני PNG בגודל 192/512. ה־service worker מעביר לרשת בלבד ואינו שומר מתכונים או API פרטי באופליין. התקנה אמיתית תלויה בדפדפן ובמכשיר.

## גיבוי הכולל מדיה ושחזור

מורידים גיבוי מעת לעת ומחזיקים עותק פרטי מחוץ לשרת. הוא מכיל מתכונים, מדיה ו־hash של סיסמת הבעלים, ולכן יש לשמור עליו כמידע אישי. הייצוא מהמסך כולל הפניות מדיה ואינו מחליף גיבוי קבצים מלא.

```sh
docker compose exec api npm run backup -- /app/backups/my-backup
docker compose cp api:/app/backups/my-backup ./my-backup
```

לשחזור משתמשים **במסד חדש וריק**, לאחר שהוחלו המיגרציות. אין לשחזר מעל מידע קיים. מעתיקים את תיקיית הגיבוי לשרת החדש, עוצרים worker ומפעילים:

```sh
docker compose stop worker
docker compose cp ./my-backup api:/app/backups/restore
docker compose exec --user root api chown -R node:node /app/backups/restore
docker compose exec api npm run restore -- /app/backups/restore
docker compose start worker
```

אין ליצור חשבון חדש לפני השחזור: חשבון הבעלים וה־hash משוחזרים מהגיבוי; אסימוני התחברות אינם משוחזרים ויש להתחבר מחדש. כל קובץ נבדק ב־SHA-256 לפני הכנסת רשומות. עבודה שאולי נשלחה ל־AI לפני גיבוי לא מתחדשת בחיוב אוטומטי. ב־S3 יש להגדיר דלי פרטי חדש או ייעודי לפני שחזור.

**נבדק בפועל:** גיבוי ושחזור של רשומות, תמונות מקור, נגזרות וסרטון למסד חדש ולאחסון חדש, ואז הפעלת שרת, התחברות וקריאת מתכון וקובץ מקור מהמערכת המשוחזרת.

לשינוי אימייל וסיסמה: עוד → ניהול החשבון. מזינים את הסיסמה הנוכחית ושומרים. זהו אותו חשבון אישי בכל המכשירים; השינוי מבטל התחברויות קודמות במכשירים אחרים ואישורי ייבוא זמניים.

במסך החשבון אפשר ליצור שמונה קודי שחזור ולהוריד אותם לקובץ פרטי. כל קוד חד־פעמי. במסך הכניסה: שכחתי סיסמה → אימייל, קוד שחזור וסיסמה חדשה. אין שליחת איפוס אוטומטי למייל. הקודים נשמרים במסד כ־hash בלבד ואינם נכללים בייצוא מהמסך; יש לשמור את הקובץ מחוץ למאגר הציבורי.

לאיפוס מנהלי אם אין סיסמה וקוד שחזור, מתוך סביבת ניהול ענן מורשית, בלי למחוק מתכונים:

```sh
docker compose exec api npm run owner:reset
```

כל ההתחברויות הקודמות יבוטלו.

## מגבלות המסלולים החינמיים

GitHub Free מתאים לקוד; הבעלים בחר מאגר ציבורי. בפריסת Neon Free הנוכחית יש מכסות מתועדות של 1GB למסד, 5GB לקבצים ו־100 CU-hours חודשיות לפרויקט. אלה מכסות תוכנית, ולא מדידת מקום פנוי. אלפי תמונות וסרטונים עשויים לחרוג מהן. פירוט ההשוואה ל־Supabase ומקורות: [docs/FREE-TIERS.md](docs/FREE-TIERS.md).

## פריסה במכשירים נוספים

הפריסה הנוכחית מספקת כתובת HTTPS ב־Render Free עם PostgreSQL ואחסון S3 פרטיים ב־Neon Free. לא נבחר מסלול מחייב. אפשר להעביר את אותה חבילה לשרת אחר עם `DATABASE_URL` ואחסון מתאים, בלי לשנות את קוד המוצר. שימוש עתידי ב־Supabase דורש בחירת פרויקט ופרטי חיבור שרת; הפרויקטים הקיימים לא שונו.

לאחר בחירת שרת והפניית דומיין אליו, מוסיפים ל־`.env` את `KITCHEN_DOMAIN` ומריצים:

```sh
docker compose -f compose.yaml -f compose.production.yaml up -d --build
```

ההרחבה מספקת Caddy עם HTTPS ועוגיות Secure. אין לחשוף את מסד הנתונים לאינטרנט, ואין להשתמש ב־HTTP במכשירים מרוחקים. רצוי לפחות 2GB זיכרון לעיבוד תמונות/וידאו ב־worker יחיד; נפח האחסון תלוי במקורות ובנגזרות. אלפי תמונות עשויות לחרוג ממכסת אחסון חינמית — בחירת הנפח נדרשת לפני העלאת האוסף.

## פיתוח ובדיקות

להרצה ללא Docker דרושים Node 24, PostgreSQL, FFmpeg ו־`heif-convert` לתמונות HEIC ש־Sharp אינו מפענח ישירות. מעתיקים `.env.server.example` ל־`.env`, מגדירים חיבור למסד ונקודות אחסון מקומיות מתאימות. מריצים מיגרציות ויוצרים בעלים. לאחר בנייה:

```sh
npm ci
npm run migrate
npm run owner:create
npm run build
npm start
```

במסוף נוסף מפעילים `npm run worker`. לפיתוח ממשק אפשר להריץ `npm run dev` בפורט 5173; קיים proxy ל־API בפורט 3000.

```sh
npm test
npm run build
DATABASE_URL=postgresql://USER:PASSWORD@localhost:5432/kitchen_test npm run test:integration
DATABASE_URL=postgresql://USER:PASSWORD@localhost:5432/kitchen_test npm run test:e2e
```

בדיקות האינטגרציה דורשות מסד בדיקה ייעודי ששמו `kitchen_test`, ומאפסות רק את ה־schema שלו. אין לכוון אותן למסד אישי. הן גם יוצרות מסד שחזור לבדיקה, ולכן משתמש הבדיקה צריך הרשאת CREATEDB. תפקיד היישום בפריסה אינו צריך הרשאה זו. בדיקות אינן מבצעות קריאות AI בתשלום. Playwright משתמש ב־Chromium מותקן או בדפדפן שהותקן באמצעות `npx playwright install chromium`.

פירוט אימות ומגבלות: [docs/ACCEPTANCE.md](docs/ACCEPTANCE.md). מבנה וקבלת החלטות: [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md).

## אימות שירותים חיצוניים ומגבלות שנותרו

- פעולות ספק AI הוסרו לפי בחירת הבעלים; אין מפתח או תקציב API הנדרשים להפעלת היישום. קובצי ספק ובדיקות היסטוריים אינם נתיבי יישום זמינים.
- Neon S3: נבדקו בענף בדיקה נפרד העלאה, הורדת מקור זהה לבייטים, thumbnail מה־worker וחסימת גישה לא מאומתת. אחסון מקומי וגיבוי מדיה נבדקו גם קודם לכן.

## ניהול אוסף גדול

בתור הייבוא בוחרים „בחירת הכול — כל העמודים”, ואז „בדיקת סיווג ואישור אצווה” ו„אישור ההצעות ושמירת המתכונים”. אין צורך להשלים כל מתכון בנפרד. ניתן לשמור גם ללא קטגוריה; שיוך מוצע מאושר רק בפעולת האישור. מקור שטרם חולץ מסומן כתמונה בלבד, ולא כחילוץ מוצלח. הבחירה כוללת עד 10,000 פריטים, והשמירה מחולקת לבקשות של עד 50 עם התקדמות ושמירה בין אצוות.

בתור ובספר המתכונים אפשר למחוק פריט או את כל הבחירה. „בחירת הכול” בספר מכבדת את החיפוש והמסננים וכוללת את כל העמודים. מחיקה דורשת אישור ומעבירה לסל מחזור; בוחרים „סל מחזור” ואז „שחזור” או „שחזור הנבחרים”. המקורות והיסטוריית הבישול נשמרים.
