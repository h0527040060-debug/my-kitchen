# תוצאות בדיקות קבלה

תאריך: 24.10.2026. כל המתכונים, החשבונות והקבצים בבדיקות הם נתונים סינתטיים נפרדים, ואינם מתכונים של הבעלים. לא בוצעה קריאת OpenAI בתשלום.

- `npm run test:unit`: עשרים וחמש בדיקות, ובהן כמויות מדויקות, חלופות, המרות, ביצים, תלויות, מזווה והשוואת חילוץ, ולצדן אתחול ענן בטוח, TLS, מגבלות Free והתאוששות מקריסת תהליך. עשר מהן מגינות גם על הקוד הקודם. בדיקת S3 משתמשת בשרת פרוטוקול מקומי מלאכותי ואינה בדיקה חיה של Supabase.
- `npm run test:ui`: חמש בדיקות הממשק הקודם עברו.
- `npm run build`: בדיקות TypeScript ובניית Vite עברו.
- `npm run test:integration`: שתים־עשרה בדיקות משנה בתוך בדיקה ראשית עם PostgreSQL, HTTP, תהליכי worker ו־FFmpeg אמיתיים. נבדקים גם יצירת בעלים ראשונה מהגדרות ענן, הגנה מפני דריסת בעלים קיים ומגבלות קבצים בפרופיל Free.
- `npm run test:e2e`: ארבע בדיקות Chromium עברו באמולציית נייד עם מגע ועברית ברוחב 390 פיקסלים. נבדק גם גובה 480 המדמה שטח מצומצם בעת הקלדה.
- `npm audit --omit=dev --audit-level=high`: לא נמצאו חולשות בחבילות הריצה בזמן הבדיקה.
- חבילת Docker נבנתה והופעלה בפועל מהתקנה נקייה עם PostgreSQL 17, API ו־worker נפרדים ו־volumes מתמשכים. נבדקו יצירת בעלים במסוף, התחברות, שמירת מתכון, עיבוד thumbnail ב־worker, חסימת מדיה לא מאומתת וגיבוי מתוך הקונטיינר. תפקיד `kitchen` אינו superuser ואינו מורשה ליצור מסדים או תפקידים; סיסמת מנהל האתחול אינה מועברת ל־API.

בדיקות האינטגרציה מאפסות רק schema במסד ייעודי `kitchen_test`. תרחיש השחזור משתמש במסד נוסף ובאחסון חדש. הבדיקות מכריחות מפתח AI ריק ותקציב אפס. ספק מלאכותי בודק התמדה וזרימה בלבד.

FFmpeg המיר בפועל סרטון ובנה poster, וגם המיר הקלטת WebM במבנה streaming ל־MP3 בסביבת הבדיקה המקומית. נוסף לכך, מתאם S3 נבדק מול דלי Neon מרוחק כמפורט בהמשך. קיים fallback ל־heif-convert ב־Docker, אך לא נמסרה תמונת HEIC אמיתית לאימות כיוון וקודק.

אין הבטחת צלצול כשהמכשיר נעול. הקראת דפדפן תלויה בקול עברי זמין; גיבוי הקול בשרת דורש חיבור AI ובדיקת מכשיר. הקוד הועלה למאגר GitHub ציבורי לפי בחירת הבעלים, ו־[בדיקות CI עברו בענן](https://github.com/h0527040060-debug/my-kitchen/actions/runs/40134033048).

## בדיקות פריסה חיה ב־Render ו־Neon

ב־24.10.2026 UTC נוצר שירות Render במסלול `free` ופרויקט Neon בארגון `free_v3`. שבע המיגרציות הוחלו תחילה בענף `deployment-check`, לפני חיבור ענף המשתמש `main`. נתוני הבדיקה סינתטיים ומסומנים; אינם נתוני הבעלים. לא נשלחה קריאה לספק AI; במסד הבדיקה נמצאו אפס רשומות שימוש AI.

- HTTPS ו־`/api/health` עברו מול שרת Render ומסד Neon אמיתיים. התחברות בעלים בעוגייה מוגנת עברה; קריאת מתכון או מקור ויצירת משימת AI בלי התחברות החזירו 401.
- אישור קטגוריה יצר ענף אחד ומשימת תמונת קטגוריה אחת. מתכון ידני נשמר ב־PostgreSQL ונקרא מחדש. תמונת הקטגוריה ממתינה לחיבור AI, ושמירת המתכון הצליחה.
- תמונת PNG סינתטית הועלתה ל־Neon Object Storage פרטי. המקור שהורד היה זהה לבייטים שהועלו; worker ב־Render יצר thumbnail שנקרא דרך השרת המאומת.
- מצב בישול בכמות שמונה נוצר ושמר סימון מצרך. משימת בדיקת AI עברה למצב `blocked` בהיעדר מפתח, והמתכון והצ׳קליסט נשארו נגישים.
- Chromium מול הכתובת הציבורית, באמולציה עם מגע ורוחב 390 פיקסלים: כניסה, פתיחת מתכון, שינוי תפוקה לחישוב 3.2, גלריה פרטית ועמוד ללא גלילה אופקית. אין בכך בדיקת טלפון פיזי או מיקרופון.
- אחרי פריסה מחדש של Render נבדקו שוב התחברות, מתכון, מקור פרטי וסימון הבישול; כולם נשמרו. זו בדיקה של חיבורי המסד והאחסון החיצוניים, ולא של המשך העלאה מקובץ מקומי לאחר סגירת דפדפן.

בדיקת המתנה מלאה לשנת Render ולהתעוררות לא נערכה. עיבוד וידאו כבד בענן, שחזור גיבוי דרך Codespaces, קול במכשיר וחילוץ/יצירה/עריכה ב־OpenAI עדיין לא אומתו בחיבור חי. בדיקת הגיבוי והשחזור המלאה שתוארה לעיל בוצעה עם PostgreSQL ואחסון מקומי בסביבת בדיקה אמיתית; אין להציג אותה כשחזור Neon בענן.

לאחר מכן חובר שירות Render לענף `main`, והפריסה `dep-dbeikevavr4c73b20sd0` הגיעה למצב `live`. נבדקו במסד הראשי שבע מיגרציות, בעלים יחיד ואפס מתכונים, מדיה ומשימות: נתוני הבדיקה לא הועברו אליו. כתובת השירות היא https://my-kitchen-k4w7.onrender.com .
