# הפעלה בענן חינמי בלי מחשב דולק

כתובת האפליקציה: **https://my-kitchen-k4w7.onrender.com**. שירות Render Free מריץ API ו־worker בתהליכי Node נפרדים. PostgreSQL, התור והקבצים נמצאים בפרויקט Neon Free ייעודי. המחשב האישי יכול להיות כבוי.

הקוד ב־[GitHub](https://github.com/h0527040060-debug/my-kitchen) ציבורי לפי בחירת הבעלים. סיסמאות, מדיה, מתכונים וגיבויים אינם במאגר. יצירת פרויקט Supabase נדחתה בשל מכסת שני פרויקטים פעילים; פרויקטים קיימים לא שונו או הושעו.

## כניסה ראשונה

1. פתח את כתובת האפליקציה בטלפון. לאחר שינה ההפעלה עשויה להימשך כדקה.
2. השתמש באימייל הבעלים שנקבע בעת הפריסה.
3. את הסיסמה הראשונית קוראים באופן פרטי ב־[Render → my-kitchen → Environment](https://dashboard.render.com/web/srv-dbei9mbrjlhs73fpnqs0/env), במשתנה `OWNER_PASSWORD`. אין להעביר סודות לצ׳אט או למאגר.
4. לחץ „כניסה למטבח שלי”. לחץ „מתכון חדש” להזנה ידנית. שמירה כמתכון מוכן דורשת תפוקת בסיס וקטגוריה מאושרת.
5. אפשר להיכנס ממכשירים נוספים של אותו בעלים ולהוסיף למסך הבית לפי יכולת הדפדפן.

חשבון הבעלים מנוהל בשרת שלנו, ללא הרשמה ציבורית וללא תלות ב־Neon Auth. `OWNER_PASSWORD` מאתחל חשבון חדש בלבד; שינוי המשתנה ב־Render אינו מאפס סיסמה קיימת. לשינוי רגיל משתמשים באפליקציה: עוד → ניהול החשבון. שם אפשר לשנות אימייל וסיסמה וליצור קודי שחזור פרטיים. במסך הכניסה „שכחתי סיסמה” מקבל קוד חד־פעמי; אין שליחת מייל אוטומטית. ללא סיסמה וקוד שחזור, משתמשים ב־`npm run owner:reset` בסביבת ניהול זמנית מורשית בענן, עם פרטי המסד הפרטיים. האיפוס מבטל התחברויות קודמות ושומר מתכונים. אחרי שמירת הסיסמה במקום פרטי אפשר להסיר מ־Render את משתני OWNER; החשבון לא יימחק.

## מה נשמר איפה

| רכיב | יעד |
|---|---|
| אתר, API ועיבוד | Render Free, שירות `my-kitchen` |
| נתוני המשתמש | Neon, פרויקט `my-kitchen`, ענף `main`, מסד `kitchen`, סכמה פרטית `kitchen` |
| קבצים | Neon Object Storage, דלי `my-kitchen-private`, הרשאת `private`, גישה דרך שרת מאומת בלבד |
| בדיקות פריסה | ענף `deployment-check` נפרד, עם נתונים סינתטיים מסומנים בלבד |
| AI | כבוי: אין מפתח OpenAI ו־`AI_DAILY_MAX_CALLS=0` |

## מגבלות החינם

Render Free נרדם אחרי 15 דקות ללא בקשות נכנסות. העיבוד מושהה בזמן שינה, אך מידע וקבצים שכבר הועלו נשמרים ב־Neon. בהתעוררות מתחדשות משימות מקומיות שפג ה־lease שלהן; קריאת AI שאולי כבר נשלחה מסומנת `uncertain` ואינה נשלחת שוב אוטומטית. אין שירות ping שנועד לעקוף שינה ואין הבטחת עיבוד רצוף 24/7.

ל־Render מכסה של 750 שעות instance חודשיות במשותף לשירותי Free בסביבת העבודה, וכן מכסות תעבורה ובנייה. הדיסק מתכלה; המקורות אינם נשמרים בו לצמיתות. פרופיל הענן דורש `STORAGE_DRIVER=s3`. אין דיסק, worker או מסד Render בתשלום.

לפי [מחירון Neon](https://neon.com/pricing), שנבדק ב־24.10.2026, Free כולל עד 100 פרויקטים, 1GB למסד, 5GB Object Storage ו־100 CU-hours חודשיות לפרויקט. יש מכסות נוספות; אלה אינן מדידות נפח פנוי. המקור והנגזרות נספרים יחד, ואלפי תמונות או סרטונים עשויים לחרוג. הפרויקט נוצר בארגון Free, ללא שדרוג או רכישה.

יש להשאיר את החשבונות במסלולים החינמיים, ללא הפעלת שדרוג או חיוב חריגות. לפי Render, חריגות תעבורה ודקות בנייה עלולות להתחייב אם קיים אמצעי תשלום; בלעדיו השירות או הבניות נעצרים במכסה. המחבר אינו מציג את אמצעי התשלום, ולכן לא אומת שכל חיוב בחשבון חסום.

בפרופיל `render-free`: תמונה עד 10MB ו־20MP, סרטון עד 25MB וחמש דקות, הקלטה עד 10MB וחמש דקות והעלאה אחת בכל פעם. המגבלות מוצגות במוצר. המקור אינו מוקטן בשקט; עיבוד כבד עשוי להיות איטי או להיכשל מחוסר משאבים.

הורדת מדיה מהאחסון לדפדפן זורמת במקטעים עם תמיכה ב־HTTP Range, בלי לטעון קובץ שלם לזיכרון בכל בקשה. ה־worker מעביר סרטונים והקלטות דרך קבצים זמניים ומעלה את התוצרים בזרימה; המקורות הקבועים נשארים באחסון הפרטי. FFmpeg מוגבל לתהליכון אחד גם ליצירת תמונת פתיחה, וגרסת הניגון מוגבלת ל־1280 פיקסלים בכל ציר בלי להגדיל מקור קטן. תמונות פתיחה מוגבלות ל־600 פיקסלים בכל ציר. `MALLOC_ARENA_MAX=2` ו־`UV_THREADPOOL_SIZE=2` מוגדרים בתמונת Docker לצמצום זיכרון פנימי של ספריות המדיה בשרת המשותף ל־API ול־worker.

## שחזור הפריסה בחשבון אחר

1. צור פרויקט Neon Free באזור נתמך לאחסון, מסד PostgreSQL ודלי Object Storage פרטי. אין צורך להחליף את מנגנון הכניסה של האפליקציה.
2. קח חיבור PostgreSQL **ישיר**, ללא `-pooler` בשם השרת. Transaction pooler אינו מתאים לנעילות החיבור במיגרציות. אימות תעודת TLS נשאר פעיל.
3. צור אישור אחסון לענף המתאים, עם `storage:read` ו־`storage:write`. במימוש S3 הנוכחי מזהה `token_id` הוא Access Key ID, ו־`s3_secret_access_key` הוא הסוד שלו.
4. ב־Render בחר New → Blueprint וחבר את המאגר. `render.yaml` צריך להציג שירות Web אחד ב־Free, בלי רכיבים בתשלום.
5. הזן באופן פרטי ב־Environment את `DATABASE_URL`, `S3_BUCKET`, `S3_ENDPOINT`, `S3_REGION`, `AWS_ACCESS_KEY_ID`, `AWS_SECRET_ACCESS_KEY`, `OWNER_EMAIL` ו־`OWNER_PASSWORD`. כתובת S3 והאזור נלקחים מהענף ב־Neon. סיסמת בעלים: 12–256 תווים.
6. השאר `DATABASE_SSL=true`, `DATABASE_POOL_SIZE=3`, `S3_FORCE_PATH_STYLE=true`, `COOKIE_SECURE=true` ו־`AI_DAILY_MAX_CALLS=0`. אם נדרשת תעודת מסד ייעודית, השתמש ב־`DATABASE_CA_PEM`; אין לכבות אימות TLS.
7. המתן לפריסה. המיגרציות ואתחול הבעלים רצים לפני השרת. אין צורך ב־Shell/SSH, שאינם כלולים ב־Render Free.
8. בדוק `/api/health`, כניסה, שמירה וקריאה מחדש, העלאה והורדת מקור, thumbnail מה־worker וגישה חסומה ללא התחברות. בדוק גם פריסה מחדש. אין להריץ בדיקות שמאפסות סכמות על מסד אישי.

השירות הקיים נוצר דרך המחבר ו־auto-deploy שלו כבוי: דחיפה ל־GitHub אינה פורסת לבדה. מפעילים Manual Deploy אחרי שינוי קוד. שינוי משתני סביבה דרך המחבר עשוי להפעיל פריסה בעצמו; בודקים פריסות לפני יצירת נוספת. ה־Blueprint מגדיר health check ל־`/api/health`; בשירות שנוצר דרך המחבר נבדקת כתובת זו במפורש בנוסף לבדיקת הפורט של Render.

## AI וגיבוי

פעולות ספק AI הוסרו מהיישום לפי בקשת הבעלים. אין להגדיר מפתח OpenAI לצורך ההפעלה. תמונות הקטגוריות מעובדות מתוך ספרייה מובנית, והייבוא נעשה דרך שיחת Work. [הנחיות AI](AI.md).

ייצוא מהמסך כולל הפניות מדיה ואינו מחליף גיבוי קבצים. `npm run backup -- תיקייה` מוריד גם מקורות ונגזרות; `npm run restore -- תיקייה` משחזר רק למסד חדש וריק עם המיגרציות. התהליך ובדיקת שחזור מלאה מתועדים ב־[README](../README.md). אפשר להשתמש בסביבת ניהול זמנית בענן, כגון Codespaces אם קיימת מכסה חינמית, ולהזין בה סודות באופן פרטי. שימוש חי ב־Codespaces לגיבוי טרם נבדק. יש להעביר את הגיבוי לאחסון פרטי קבוע לפני סגירת הסביבה; אין לדחוף אותו למאגר הציבורי.
