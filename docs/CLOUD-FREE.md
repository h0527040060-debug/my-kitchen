# הפעלה בענן חינמי בלי מחשב דולק

העדפת הבעלים: שירותים חינמיים בלבד, תוך קבלת מגבלות זמינות ונפח. קובץ הפריסה מכוון ל־Free בלבד. לא נבחר שירות בתשלום ולא נוצר חיוב. המשתמש יכין פרויקט Supabase ייעודי וימסור את שמו; לא נוגעים בפרויקטים הקיימים.

## מה רץ איפה

| רכיב | יעד |
|---|---|
| קוד | מאגר GitHub פרטי |
| אתר, API ועיבוד | שירות Render Free אחד, עם תהליך Node ל־API ותהליך Node נפרד ל־worker |
| מסד ותור מתמשך | PostgreSQL של פרויקט Supabase הייעודי, בסכמה פרטית `kitchen` |
| תמונות מקור ונגזרות | bucket פרטי ב־Supabase Storage, דרך S3 API בצד השרת |
| HTTPS | כתובת `onrender.com` שמספק Render; אין חובה לקנות דומיין |
| AI | אינו מופעל כברירת מחדל; OpenAI API הוא שירות נפרד שדורש מפתח ותקציב מפורש |

המחשב יכול להיות כבוי. אין צורך להתקין עליו Docker, Node או מסד לצורך המסלול הזה.

## מגבלות שנבדקו בתיעוד

Render Free נרדם אחרי 15 דקות ללא בקשות נכנסות. בקשה חדשה מעירה אותו, בדרך כלל אחרי כדקה. במהלך שינה העיבוד אינו רץ; משימות ממתינות ומצב הבישול נשמרים ב־Supabase. אחרי התעוררות worker מחדש עבודות מקומיות שפג ה־lease שלהן; קריאת AI שאולי כבר נשלחה עוברת ל־uncertain ולא נשלחת שוב אוטומטית.

התוכנית כוללת 750 שעות instance לחודש לכל workspace, במשותף עם שירותים חינמיים אחרים שלו. יש גם מכסות בנייה ותעבורה. בהגעה למכסה השירות עשוי להיעצר; אין הבטחת זמינות של 24/7. לא מוסיפים שירות ping שנועד לעקוף את השינה.

**כדי להישאר בחינם בלבד משתמשים ב־workspace ללא אמצעי תשלום.** לפי Render, חריגת תעבורה או דקות בנייה עשויה להתחייב גם כשסוג המחשב הוא Free, אם קיים אמצעי תשלום. ללא אמצעי תשלום השירות או הבניות נעצרים במכסה. אין להוסיף כרטיס או לאשר חריגות במסגרת המסלול הזה; אם החשבון דורש זאת, נדרשת בדיקת חלופה לפני פריסה. גם תעבורה יוצאת חריגה מהשירות למסד או לאחסון יכולה לגרום להשעיה.

הדיסק של Render Free מתכלה: קבצים מקומיים יכולים להיעלם אחרי שינה, פריסה או אתחול. לכן נדרשים מסד חיצוני ו־S3 פרטי. אין להחליף את STORAGE_DRIVER ל־local. אין להשתמש במסד Render Free לפריסה זו: לפי התיעוד הוא פג אחרי 30 ימים.

Supabase Free מתעד 500MB למסד ו־1GB לאחסון מדיה. אלה מכסות תוכנית, לא מקום פנוי שנמדד בפרויקט שלך. המקור והנגזרות נספרים יחד; סרטונים מצמצמים את מספר המתכונים שייכנסו. אין הבטחה לאחסן אלפי תמונות ללא תשלום. פרויקט בעל פעילות נמוכה עשוי להיעצר ויש לעקוב אחרי התראות הספק. לא משדרגים אוטומטית.

לשרת Free יש משאבים מצומצמים. בפרופיל זה: תמונה עד 10MB ו־20MP, סרטון עד 25MB/חמש דקות, הקלטה עד 10MB/חמש דקות והעלאה אחת בכל פעם. Sharp ועיבוד הווידאו מוגבלים במקביליות. הגבלות אלה מוצגות בממשק ואינן מוחקות או דוחסות את המקור בשקט. עיבוד וידאו כבד עשוי להיות איטי או להיכשל מחוסר משאבים; יש לבדוק דגימה קצרה בפועל אחרי הפריסה.

## 1. הכנת פרויקט Supabase ייעודי

1. ב־Supabase בחר פרויקט חדש או ייעודי פנוי, במסלול Free. אם אין מכסה לפרויקט נוסף, אין לשדרג או לעצור מערכת קיימת כדי לעקוף זאת. נדרש יעד חינמי מתאים לפני החיבור.
2. שמור את סיסמת המסד באופן פרטי. ב־Connect העתק URI של Session pooler בפורט 5432, או חיבור Direct אם שרת האירוח תומך בו. אין להשתמש ב־Transaction pooler לצורך המיגרציות ונעילות החיבור של יישום זה.
3. פתח Storage וצור bucket בשם `my-kitchen-private`. השאר Public לא מסומן. הגדר מגבלת קובץ שאינה נמוכה ממגבלות המוצר המתוכננות, עד מגבלת הספק החינמית.
4. ב־Storage Settings / S3 Access Keys צור זוג מפתחות שרת. שמור Access Key ID, Secret Access Key, endpoint ו־region בדיוק כפי שהם מוצגים בפרויקט. מפתחות S3 עוקפים RLS ויכולים לגשת לכל buckets בפרויקט, ולכן היעד הוא פרויקט ייעודי והמפתחות נשארים רק בשרת.
5. אין לפתוח את הסכמה `kitchen` ב־Exposed schemas ואין ליצור מדיניות ציבורית למדיה. הגישה היא דרך השרת עם חשבון הבעלים.

אין להדביק סיסמה, URI המכיל סיסמה או Secret Access Key בצ׳אט. את הסודות מזינים בהגדרות Render.

## 2. מאגר GitHub בלי התקנה מקומית

1. בחשבון GitHub צור מאגר פרטי ריק, למשל `my-kitchen`.
2. מסור בשיחה את כתובת המאגר. יצירת מאגר אוטומטית נכשלה בעבר בגלל הרשאת החיבור. אם החיבור אינו רואה את המאגר החדש, הוסף אותו לרשימת המאגרים המורשים באפליקציית GitHub המחוברת.
3. לאחר שהקוד הועלה, ודא ש־`render.yaml` ו־`Dockerfile` נמצאים בשורש המאגר. `.env`, סודות, גיבויים ומדיה אינם מועלים.

## 3. יצירת שירות Render Free

1. פתח חשבון ב־Render ובחר סביבת עבודה חינמית ללא אמצעי תשלום, כדי שחריגות מכסה יעצרו שירות במקום ליצור חיוב. התחבר ל־GitHub ואשר גישה למאגר האפליקציה בלבד ככל שהממשק מאפשר.
2. בחר New → Blueprint, בחר את המאגר והענף שבו הקוד החדש, ואשר שימוש ב־`render.yaml`.
3. בדוק שמוגדר שירות Web אחד ב־Free, ושאין רשומות בתשלום של Worker, Database או Disk. אם מוצג חיוב חובה, אין להמשיך במסלול זה בלי לשנותו ל־Free או לבדוק חלופה.
4. מלא את הערכים שה־Blueprint מבקש:

| משתנה | מה להזין |
|---|---|
| DATABASE_URL | URI של PostgreSQL מפרויקט Supabase הייעודי, כולל סיסמת המסד וקידוד תקין לתווים מיוחדים |
| S3_BUCKET | `my-kitchen-private` |
| S3_ENDPOINT | endpoint שמוצג בהגדרות S3 של הפרויקט |
| S3_REGION | region שמוצג בהן |
| AWS_ACCESS_KEY_ID | Access Key ID של S3 |
| AWS_SECRET_ACCESS_KEY | Secret Access Key של S3 |
| OWNER_EMAIL | האימייל שישמש אותך להתחברות לאפליקציה |
| OWNER_PASSWORD | סיסמת בעלים חדשה באורך 12–256 תווים |

5. אשר את יצירת השירות החינמי והמתן לבנייה. Render מגדיר כתובת HTTPS דרך RENDER_EXTERNAL_URL; הקוד גוזר ממנה את כתובת המקור ומפעיל עוגייה Secure.
6. אם מופיעה שגיאת אימות תעודת PostgreSQL, קח את תעודת ה־CA מהפרויקט והוסף אותה כ־DATABASE_CA_PEM. אפשר ערך PEM מרובה שורות או רצפי `\n`. אין לכבות אימות תעודות.
7. פתח את כתובת ה־onrender.com שמוצגת והתחבר. בפעם הראשונה נוצר בעלים מהערכים הפרטיים. באתחולים הבאים חשבון קיים אינו מוחלף גם אם משתני OWNER השתנו. אין מסלול הרשמה ציבורי.
8. אחרי כניסה מוצלחת אפשר להסיר את OWNER_EMAIL ואת OWNER_PASSWORD מהגדרות השירות. לשינוי סיסמה קבוע יש להשתמש בכלי האיפוס המתועד מתוך מסוף ניהול מורשה; שינוי משתנה OWNER_PASSWORD אינו מאפס חשבון קיים.

ל־Render Free אין Shell/SSH של השירות. לכן אין צורך להריץ בו docker compose exec או פקודת יצירת בעלים; תהליך האתחול מספק את ההקמה הראשונה. Render מנהל את הקונטיינר, ואין צורך ב־Docker במחשב שלך.

## 4. בדיקות לאחר הפריסה

1. שמור מתכון ידני, טען מחדש ופתח אותו ממכשיר נוסף.
2. העלה תמונה קטנה ובדוק שנוצרה תמונה ממוזערת ב־worker. פתח את המקור בזום.
3. בדוק ב־Storage שה־bucket נשאר פרטי. בחלון דפדפן ללא התחברות אין גישה לנתוני מתכונים או ל־API של המדיה.
4. הפעל Redeploy של השירות ובדוק שהמתכון, המקור והצ׳קליסט עדיין קיימים. בדיקה זו מאמתת שאינם תלויים בדיסק המתכלה.
5. בדוק אחרי שינה של השירות שהתור מתחדש. אל תספור כתיבה מדומה או דגימת SDK כבדיקה חיה של Supabase.
6. בדוק וידאו קצר לפני אוסף גדול. יש להפריד בין בדיקת FFmpeg מקומית לבין הצלחה במשאבי Render Free.

## 5. AI וגיבויים

AI_DAILY_MAX_CALLS נשאר 0 ואין מפתח OpenAI ב־Blueprint. הפעלת AI דורשת החלטת תקציב ומפתח נפרדים לפי [AI.md](AI.md). חינם באירוח אינו חינם ב־API. בדיקות המודלים אינן מוכיחות איכות חילוץ עברית.

ייצוא הנתונים מתוך האפליקציה כולל הפניות מדיה ואינו מחליף גיבוי מלא. פקודת `npm run backup -- תיקייה` יכולה לפעול מתוך סביבת ניהול זמנית בענן, למשל Codespaces אם מכסת החשבון החינמית מאפשרת זאת: מגדירים בה באופן פרטי את אותו DATABASE_URL ואותם פרטי S3, מתקינים dependencies, ומריצים את הפקודה. היא מורידה גם את המקורות והנגזרות. יש להוריד את הגיבוי למקום פרטי וקבוע לפני מחיקת סביבת הניהול. אין לשמור גיבוי במדיה הזמנית של Render או לדחוף אותו ל־GitHub. תהליך Codespaces חי לא נבדק כאן.

## מה הוכן ומה עדיין לא אומת

הוכן Blueprint חינמי, אתחול בעלים ללא Shell, מנהל תהליכים ל־API ול־worker, בדיקת אחסון חיצוני מחייבת, TLS למסד ומגבלות מדיה התואמות לפרופיל. הקוד ו־render.yaml הועלו ל־[מאגר GitHub](https://github.com/h0527040060-debug/my-kitchen) בענף main, והבדיקות עברו גם ב־GitHub Actions. המאגר ציבורי לפי בחירת הבעלים; אין בו סודות או נתוני שימוש.

Render מופיע כתוסף מותקן ומופעל, אך כלי ניהול החשבון טרם זמינים בשיחה הנוכחית. פרויקט Supabase הייעודי שהבעלים יכין עדיין אינו מופיע בחיבורים. אלה החיבורים החסרים לפריסה חיה; לא פורסמה כתובת אפליקציה ולא בוצע חיוב.

מקורות שנבדקו: [Render Free](https://render.com/docs/free), [Blueprint specification](https://render.com/docs/blueprint-spec), [Supabase S3 authentication](https://supabase.com/docs/guides/storage/s3/authentication), [חיבור PostgreSQL](https://supabase.com/docs/guides/database/connecting-to-postgres), [מכסות Supabase](https://supabase.com/docs/guides/platform/billing-on-supabase).
