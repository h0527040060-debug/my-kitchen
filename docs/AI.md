# מנועי AI והפעלה חיה

## המסלול שנבחר כעת: קריאה בשיחה וייבוא טיוטות

הבעלים בחר לעבד תמונות בתוך שיחת ChatGPT Work ולייבא את התוצאה לאפליקציה, הן מ־Drive והן מצירוף תמונות לשיחה. זרימה זו אינה קוראת OpenAI/Gemini API מתוך השרת, ואינה דורשת מפתח שלהם. היא משתמשת במכסות מנוי ChatGPT ובהרשאות החיבורים הקיימים, ולא מספקת worker של ChatGPT שפועל כשהשיחה אינה פעילה. המקור נשמר פרטי וכל סיווג דורש אישור. [הנחיות מלאות](CHAT-IMPORT.md).

החיבור ל־OpenAI המתואר בהמשך נשאר אפשרות נפרדת וכבויה. קריאת תמונות בשיחה אינה בדיקת חיבור או מדד דיוק של OpenAI API או Gemini API.

שמות המודלים והממשקים נבדקו בתיעוד הרשמי ב־24.10.2026. התיעוד אינו הוכחה שהחשבון שלך מורשה להשתמש בהם.

| פעולה | משתנה | ברירת מחדל | מאמץ / איכות |
|---|---|---|---|
| חילוץ עברית ותמונה | `RECIPE_VISION_MODEL` | `gpt-6.1-sol` | `RECIPE_VISION_EFFORT=high` |
| סיווג, חיפוש, עזרה ותפריטים | `RECIPE_ASSISTANT_MODEL` | `gpt-6.1-sol` | `RECIPE_ASSISTANT_EFFORT=medium` |
| יצירת תמונה | `IMAGE_GENERATION_MODEL` | `gpt-image-2.5-flare` | `IMAGE_QUALITY=medium` |
| עריכת תמונה | `IMAGE_EDIT_MODEL` | `gpt-image-2.5-sunburst` | `IMAGE_EDIT_QUALITY=high` |
| תמלול הקלטה כשאין זיהוי דפדפן | `TRANSCRIPTION_MODEL` | `gpt-transcribe` | File transcription |
| הקראה כשאין קול עברי בדפדפן | `SPEECH_MODEL` | `gpt-realtime-2.1-mini` | Realtime WebSocket, PCM → WAV |

החילוץ משתמש ב־Responses API וב־JSON Schema עם Structured Outputs; יצירה ועריכה משתמשות ב־Images API. אין התייחסות למודל תמונות כ־OCR. הקוד משתמש ב־SDK הרשמי `openai`, בגרסה נעולה בקובץ החבילות. `AIProvider` מפריד את שש פעולות הליבה; פרטי ספק ממוקמים בשרת בלבד.

## חיבור

1. יש להגדיר `OPENAI_API_KEY` בקובץ `.env` הפרטי של השרת, או במנהל הסודות של האירוח. אין להגדירו במשתנה `VITE_*`, להעלות אותו ל־Git או להדביקו לקוד.
2. `AI_DAILY_MAX_CALLS=0` משבית חיוב כברירת מחדל. לאחר החלטה להפעיל API, יש לבחור מכסה יומית. אפשר להגדיר מכסה אישית נמוכה יותר במסך עוד. ספירה זו כוללת ניסיונות שנשלחו ואת רישומי הבקשות שנדחו; היא שמרנית ואינה חיוב כספי.
3. מפעילים מחדש API ו־worker. עבודות חסומות אינן מתחדשות אוטומטית אחרי שינוי מפתח: אפשר לבחור ניסיון חוזר במסך העבודות.
4. ״בדיקת גישה למודלים״ קוראת את קטלוג החשבון ומציגה גם `operation_tested=false`. היא אינה מציגה זאת כבדיקת OCR, יצירה או עריכה.
5. בדיקה חיה מפורשת של שלוש פעולות:

   ```sh
   AI_SMOKE_ALLOW_PAID=true npm run ai:smoke -- /path/to/real-recipe.jpg data/ai-smoke
   ```

   יש לוודא תחילה שמפתח ותקציב קריאות מוגדרים. זו פעולה בתשלום אפשרי, ואינה רצה בבדיקות אוטומטיות. מספר קריאות אינו מבטיח סכום דולר מסוים; לשמירת תקציב יש להשתמש גם במגבלות הפרויקט אצל הספק. אין להריץ אותה בלי הרשאה לתקציב.

הבדיקה שומרת חילוץ ותמונות בתיקייה פרטית שלא נכנסת ל־Git. גם כאשר שלוש הקריאות הצליחו, היא מסמנת `accuracy_verified=false`: צריך להשוות לתמונה האמיתית, במיוחד כמויות, שברים, יחידות, חלופות וקישור להוראות.

## עלויות ואי־ודאות

כל קריאה מתעדת פעולה, מודל, גרסאות פרומפט וסכמה, מצב, משך ושימוש שדווח. עלות נשארת לא ידועה ללא טבלת מחירים תקפה. `AI_PRICING_JSON` יכול להכיל טבלה שהמפעיל אימת, במבנה:

```json
{"as_of":"2026-10-24","valid_until":"2026-11-24","models":{"MODEL_ID":{"input_per_million":2,"cached_input_per_million":0.2,"image_input_per_million":2,"output_per_million":10}}}
```

המספרים כאן מדגימים מבנה בלבד: יש לאמת מחיר לכל מודל לפני הגדרה. הערכה אינה חיוב בפועל. מחירים חסרים או פגי תוקף לא משמשים להצגת עלות. אין קריאות AI לחישובי כמויות, פתיחת תמונה, מיון או סימון צ׳קליסט.

ה־SDK מוגדר ללא ניסיונות חוזרים אוטומטיים. רק 429 ידוע כבקשה שנדחתה מקבל ניסיונות חוזרים מוגבלים. כשל אחרי שליחה, timeout או קריסת worker אחרי שליחה עוברים למצב `uncertain`. אין שליחה מחודשת אוטומטית; נדרש אישור מודע לכך שייתכן חיוב נוסף. מזהה תגובת Responses נשמר בהקדם, ותוצאת החילוץ נרשמת לפני הצעת סיווג נוספת. אין הבטחה ל־exactly-once מול ספק חיצוני.

## מה עדיין לא אומת בחיבור חי

בסביבה הנוכחית לא הוגדר מפתח API ולא סופקו תמונות מתכונים אמיתיות. לא בוצעו קריאות בתשלום ולא אומתה גישה של החשבון למודלים. בדיקות ספק מלאכותי בודקות זרימה והתמדה בלבד, ואינן מודדות איכות OCR. קול עברי מחייב בנוסף בדיקת מכשיר, מיקרופון, הרשאות ואיכות פלט.
